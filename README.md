## 它做了什么

把「上完课 → 对着空白框发呆 → 凑一段流水账」变成「填信息 → 自动生成 → 直接复制发家长」。

```
填学生信息 / 传讲义  →  选模式（课前 / 课后 / 两者）  →  AI 生成  →  不满意？一句话精修  →  复制发送
```

你拿到的不是"今天讲了什么"的复述，而是一条**让家长建立确定感**的专业反馈：

| 产出 | 给谁 | 解决什么 |
|------|------|---------|
| **课后反馈文案** | 发给家长 | 让家长清楚孩子"在哪个阶段、有什么问题、接下来干什么" |
| **课前通知文案** | 发给家长 | 上课前就让家长感到"这老师有备而来" |
| **历史记录** | 给你自己 | 每条反馈自动存档，按学生回溯，避免重复 |

## 核心理念

> 这是整个工具的灵魂，也是它和"随便套个 AI 模板"的根本区别。

**课后反馈的本质，不是"汇报进度"，而是帮家长"建立确定感"。**

家长在孩子出分之前，没法直接验证你的价值，只能靠你的反馈判断"这笔钱花得值不值"。所以——

| ❌ 大多数人这么写 | ✅ 这个工具这么写 |
|------------------|------------------|
| 今天讲了函数，做了 8 道题 | 孩子正处在从基础到提高的过渡阶段 |
| 孩子状态不错，挺认真的 | 公式会背，但还不会迁移到应用题 |
| 继续加油就好 | 下节课重点练应用题建模，家长可督促订正错题 |
| 流水账，信息密度极低 | 具体、微观、有阶段感 = 专业感 = 续费 |

每条课后反馈都围绕四个家长真正关心的模块展开：

| 模块 | 回答什么 |
|------|---------|
| 🎓 **孩子当前阶段** | 我的孩子现在在什么水平、什么阶段？ |
| 📊 **学习状态判断** | 今天理解得怎么样、专注度如何？ |
| 🔬 **专业洞察** | 有什么"只有真盯着学的人才看得出来"的细节？ |
| 🧭 **下节课预告** | 接下来打算怎么推进、家长要配合什么？ |

## 三种模式

| 模式 | 什么时候用 | 生成内容 |
|------|-----------|---------|
| 📨 **课前通知** | 上课前 | 上课提醒 + 本节课目标 + 课前准备 |
| 📋 **课后反馈** | 下课后 | 当前阶段 + 状态判断 + 专业洞察 + 下节课预告 |
| 🔁 **课前 + 课后** | 一次搞定 | 两份文案一起出，用分隔线隔开 |

外加两个高频小功能：

| 功能 | 说明 |
|------|------|
| ✍️ **陪写作业模式** | 不是上新课、只是陪写作业时，切换成"完成情况 + 表现观察 + 错题重点 + 下节预告"的专用结构 |
| 🛠️ **一句话精修** | 生成结果不满意？输入"语气再亲切点 / 第二段太长"，只改你点到的地方，其余不动 |

## 防雷同引擎

长期给同一个家长发反馈，最怕**每条都长得一样**——家长一眼就看出是敷衍。

本工具内置 **8 种写作角度**，每次生成自动轮换（且避开最近用过的两种），让同一个学生的连续反馈也保持新鲜感：

| 角度 | 切入方式 |
|------|---------|
| 🔍 发现式 | 从一个课堂微观细节切入："今天注意到一个细节……" |
| ⚖️ 对比式 | "之前……现在……"，制造进步感或暴露问题 |
| 🎯 目标式 | 先立目标，再评进度，最后给差距 |
| 🩺 问题导向式 | 抓最突出的一个问题，表象 → 原因 → 解法 |
| 📖 叙事式 | 用一个课堂小故事串起整份反馈 |
| ✨ 亮点优先式 | 先夸具体进步，再自然过渡到待改进（适合焦虑家长） |
| 🧭 阶段定位式 | 开篇先给孩子当前阶段下个清晰锚点 |
| 🏠 家长行动式 | 以"家长本周能做什么"为主线 |

## 学你的文风

每个老师说话的方式都不一样——有人亲切口语，有人简洁专业。AI 默认写出来的，往往不像"你"。

把你过去写过的几条反馈粘进去，工具会自动提炼出一段**可执行的文风描述**（语气、用词、结构、与家长的沟通定位），存进你的档案。之后每次生成，都照着"你的语气"来写。

```
粘贴历史反馈  →  AI 提炼文风  →  存入档案  →  以后每条都像你本人写的
```

> 还支持多用户、多学生档案管理：按学生分别保存信息与历史，带几个学生都不乱。

## API 配置

本工具不内置任何大模型，**用你自己的 API Key**，灵活又省钱。在页面右上角填三样东西即可：

| 字段 | 填什么 | 举例 |
|------|--------|------|
| **API 地址** | 供应商的接口地址 | `https://api.deepseek.com` |
| **API Key** | 你的密钥 | `sk-xxxxxx` |
| **模型名称** | 要用的模型 | `deepseek-chat` |

支持两类接口，覆盖国内外主流模型：

| 类型 | 兼容供应商 |
|------|-----------|
| **OpenAI 兼容** | DeepSeek · Kimi / Moonshot · 通义千问 · 智谱 · OpenAI 等 |
| **Anthropic** | Claude 系列 |

> 💡 写课后反馈这类任务，DeepSeek、Kimi 等国产模型性价比很高，单条成本几乎可忽略。

## 项目结构

```
jiajiao-feedback-tool/
├── app.py                  # Flask 后端：文件解析 + 多供应商调用 + Prompt + 路由
├── requirements.txt        # 依赖（flask / requests / python-docx / PyMuPDF）
├── templates/
│   └── index.html          # 单页前端
├── static/
│   ├── style.css           # 样式
│   ├── cover.jpg           # 封面
│   └── fonts/zhukai.ttf    # 字体
└── data/                   # 用户 / 学生 / 历史数据（已 gitignore，不上传）
    ├── users.json
    └── feedback_history.json
```

**后端做了什么：**

- 📄 **文件解析** — PDF（PyMuPDF）、Word（python-docx）、TXT（自动识别 UTF-8 / GBK / GB18030）一键提取讲义
- 🔌 **多供应商路由** — OpenAI 兼容接口与 Anthropic 接口统一入口，自动补全 URL、统一错误提示
- 🧠 **Prompt 工程** — 内核理念 + 四模块结构 + 8 角度轮换 + 文风注入，全部沉淀在服务端
- 💾 **本地存储** — 用户、学生、历史均为本地 JSON，零数据库依赖，开箱即用
